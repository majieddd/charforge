System overview

CharForge has two lanes that share one skeleton ([#fig-pipeline]). The character lane (charforge.py make, 23 stages) builds a character once, from a prompt or an image. The move lane (charforge.py move) adds a move from a generated video to any character; because every clip it produces is on the standard Mixamo skeleton, one video serves every character. Both lanes are Python and headless Blender [@blender] around local models: an image model for the reference [@qwenimage2], TRELLIS.2 [@trellis2] through its MLX port [@trellis2mlx] for the 3D model, a human parser [@segformer] for part labels, ViTPose [@vitpose] and DWPose [@dwpose] for pose, U2-Net [@u2net] for cut-outs, a small language model [@gemma] for prompts, and a reference-to-video model [@h3] through ComfyUI [@comfyui]. A browser application, the Studio, runs the same stages for a user without the command line ([#fig-studio-new]).

Where the time goes. [#tab-times] gives the median time of each stage over every build logged on this machine. Four stages - the second, multi-view 3D pass, the reference image, the first 3D pass and the texture projection with its detailed face - take {{stage.top4.min}} of the {{stage.total.min}} minutes; everything that turns the generated mesh into a rigged, animated character takes under five. The times include any wait for the GPU while another job held it ([#sec-m-runtime]), so they are what a user waited, not each stage's own cost; timing each stage alone, and cutting what the measurements say is not worth its time, is experiment [E106].
